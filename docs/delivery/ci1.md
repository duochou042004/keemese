## Pipeline contract

- Standard GitHub-hosted `ubuntu-24.04`, read-only contents token, checkout without persisted credentials, official actions pinned to verified full commit SHAs with version comments. Recheck release/runtime compatibility in primary sources; dated action candidates in the runbook are not trusted pins. No `pull_request_target` execution of untrusted code, write tokens, external secrets or self-hosted runners.
- Keep the workflow small: lightweight classification/docs validation plus one conditional Linux verification job is a reasonable default. Avoid rebuilding the same backend/frontend for separate browser jobs. No Windows/macOS matrix, schedule, CD or heavy security platform in this packet.
- Trigger on pull requests and relevant branch pushes, including a safe way to verify the initial workflow on the existing feature branch without merging. Avoid redundant full push/PR runs where they test the same state; preserve PR merge-state validation. Cancel superseded runs per branch/PR; use bounded job/command timeouts. Choose auditable event logic and record it; do not rely on workflow_dispatch for a workflow that does not exist on the default branch yet.
- Classify from reliable Git revisions: docs-only changes run fast JSON/JSONL/local Markdown target/traceability/whitespace checks; backend changes run backend verification and browser journeys; frontend changes run frontend verification and browser journeys (which need a built backend); CI/shared SDK/lock/test/helper changes run full verification. Missing base, rename/deletion, initial push and unknown paths must default conservatively. Do not silently skip tests because classification failed. Demonstrate docs/backend/frontend/shared/unknown classifier cases and a stable overall result that fails on failed/cancelled prerequisites, rather than a green skipped check. Avoid top-level path filters that leave required checks pending. No branch-protection settings are changed.
- Lockfile-keyed NuGet and npm download caches; never cache credentials, private data, DB state or `node_modules`. Start without large browser/container caches unless measured savings justify them. Install only Chromium for exact locked Playwright; avoid expensive browser matrices. Save small reports on failure with short retention (e.g. three days), explicit paths/size limits, no raw environments/cookies/DB credentials/traces or blanket workspace upload. Existing successful-run screenshot matrices can remain ephemeral on the runner; do not upload all PNGs or commit generated QA from CI.
