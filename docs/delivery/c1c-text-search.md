# C1c — native-text library search proposal

Approved 2026-10-29, Asia/Ho_Chi_Minh by the user: “I approve. Proceed with the next steps according to the plan—right here, right now.” This supersedes the fresh-chat-only start condition for this bounded packet; it is not evidence of fresh-session context safety. This packet makes existing tutor-created text findable; it does not complete C1/A3. The authoritative specification sections 12–13, 32 and 51 support organizing/reusing tutor sources and separating them from student activity. The detailed search rules below are proposed product choices, not requirements invented from those sections.

## Concrete behavior

Search title, description and teaching body, matching if **any one field** contains the entire query. Use one literal substring, including partial words and phrases; do not tokenize or match across field boundaries. No stemming, ranking, fuzzy matching, regex, wildcard syntax, accent removal, folder-name search, snippets or highlighting. `%`, `_`, backslash, quotes and HTML-shaped input are ordinary text. A body-only hit still shows the existing title/description summary; opening it shows the saved body.

Define the search transform precisely as `NFC(ToUpperInvariant(NFC(value)))`, applied identically to each searchable field and the query in the pinned .NET runtime. This is invariant uppercase matching, not a promise of full Unicode case folding or language-specific equivalence. Vietnamese `tiếng`/`TIẾNG` and canonically equivalent composed/decomposed input must match. `tieng` does not match `tiếng`; `d` does not match `đ`. No compatibility normalization: full-width characters and ligatures are not deliberately expanded. Emoji and supplementary characters remain literal. Runtime/Unicode upgrades require the fixture suite and a separately planned projection rebuild for retained data.

Accept optional single `q` on the existing GET list endpoint. Omitted, empty or outer-whitespace-only means no search. Before trimming, cap decoded input at 200 UTF-16 code units (same units as existing content limits); allow 1–200 after trimming, then transform. Do not collapse internal spaces or replace line breaks in saved content. Reject query NUL, invalid Unicode scalar sequences and internal control characters (Unicode category Cc, including tabs/newlines) with 400 `invalid_content_search`; outer whitespace is trimmed using .NET `Trim`. Check the raw cap first, so 201 spaces are invalid. No truncation. Browser uses the same 200-unit limit and client validation for a useful message; server remains authoritative. A single-line input may differ in native paste handling, so direct API tests own the complete contract.

Examples: `  Perfect  ` searches `PERFECT`; `present perfect` matches that contiguous phrase in one field, but not `present  perfect` or text split by a newline. Empty search retains the current list exactly. Authored content bytes and current title trimming remain unchanged.

## Filters, pagination and requests

`GET /api/v1/content?archived=false&page=1&pageSize=25&q=...` keeps `{items,nextPage}` and existing summary DTOs. Search intersects active/archived status and all/direct-folder/unfiled filtering. Default remains active/all; archive is never implicitly included. Unknown valid folder IDs still yield an empty list. No descendant traversal. Keep updatedAt descending then ID ascending, existing size 1–100 and page 1–1,000,000 limits, and size+1 lookahead; return no total count. Deterministic order is not a snapshot across requests: edits/archive/moves between pages may shift results. An out-of-range page is empty with Previous available, not a false claim that the entire library is empty. At maximum page, never emit a nextPage beyond the accepted bound.

Add a labeled search form above the list, after folder/status controls, with explicit Search and Clear buttons. Submit by button or Enter; no debounce or requests while typing. Ignore Enter during IME composition. Keep separate draft input and applied query. Show the applied query as plain React text near the results so unsubmitted edits cannot mislabel them. A changed valid submit or Clear resets page to 1; a same-query submit refreshes page 1 once. Clear empties draft and applied search, preserves folder/status and returns focus to input. Clear is also available when only an unsubmitted draft exists. Folder/status changes reset page 1 and reuse the applied query without submitting or discarding draft input. Pagination and Retry reuse the applied query. Folder mutations refresh from page 1. All list state is memory-only; leaving the library resets it, as today. Do not put query/content in router URLs, browser storage or history.

Input stays editable during loading. Permit a newer submit/filter/page change; guard each response/error/finally by current request generation or effect cleanup, retaining the existing ApiClient account epoch and timeout behavior. Superseded results must never replace newer state, even if cancellation is unavailable. Clear old rows immediately on a new applied request; show a polite loading status and hide/disable stale pagination. Prevent duplicate pending submissions for the identical tuple. Retry makes one request for the failed tuple; no automatic retry loop. Search remains read-only and does not refresh or replace editor/folder drafts.

No-result copy distinguishes a nonempty applied search (“No matching content” / “Không tìm thấy nội dung phù hợp”) from an empty folder/library/archive; offer Clear search while retaining folder/status. Page >1 emptiness instead says this page has no results and offers Previous. Keep transient failure separate from no results. Validation is associated with the input and focuses it on invalid submit. Ordinary submit, results, failure, Retry and locale change must not steal focus; announce completion/loading/errors through existing accessible notices or a polite status as appropriate. Use existing deep-blue/white controls and 44px targets.

Both language dictionaries cover labels, helper text (“Search title, description and teaching text. Accents matter.”), Search/Clear, applied-query context, loading, validation, no-match and retry/page states. Language switching preserves raw/applied query, folder/status/page, focus/selection and pending request; it changes labels/messages live without requests. Never translate authored text or interpolate query as HTML. Existing editor unsaved/stale behavior remains intact.

## API, persistence and query choice

Current `TextLibrary.ListAsync` filters, orders, skips and projects server-side; it has no search. The model has archive/order and folder/archive/order B-tree indexes. `ContentLibrary` already uses a live-effect guard, and ApiClient resets/aborts on identity transitions. Extend these paths rather than adding another search service or client-side library download.

Allow only existing list keys plus `q`. Reject repeated list keys (even identical values) and unknown keys rather than accepting comma-joined values; retain `invalid_pagination` for existing selector errors and use `invalid_content_search` for q errors. Validate after existing tutor/session authorization, never expose validation details to unauthorized callers. Encode via URLSearchParams. GET remains read-only, no CSRF exemption changes; existing origin/session/case/no-store policy and POST CSRF remain. Do not accept author/student selectors or expose body/search projections in summaries. No query text in errors, audit or new logging/telemetry. Query strings necessarily transit GET infrastructure; production request-log redaction remains a deployment prerequisite, not a claim of current hosted privacy.

Propose three internal nonnullable PostgreSQL text columns (`SearchTitle`, `SearchDescription`, `SearchBody`), each with deterministic `C` collation. Populate the transform on create/edit within the existing content/audit transaction, sharing the existing structural lock/version guard. Archive/restore preserve projections. Preserve original fields for display and detail DTOs. Reject malformed source Unicode with existing invalid-content codes before normalization, avoiding a new 500 path. No new search audit event or version bump on reads. Tests must prove projection rollback and refresh after successful edits, plus no change on stale/failed edits. Ordinary text columns avoid an external index or extension, at the cost of duplicating normalized content and write work.

Use a parameterized server-side predicate equivalent to `strpos(SearchTitle, @q) > 0 OR strpos(SearchDescription, @q) > 0 OR strpos(SearchBody, @q) > 0`, combined with existing filters before order/skip/take. Prefer the documented Npgsql `IndexOf(string) >= 0` translation; inspect generated SQL and exercise the installed Npgsql 10.0.3 provider. Do not assume current online docs prove that pinned version, or use the StringComparison overload/client evaluation. Empty q omits this predicate. No concatenation of fields, interpolated SQL or LIKE/ILIKE wildcard leakage.

Alternatives reviewed: ILIKE/lower depend on database locale and do not alone establish canonical equivalence; full-text changes word/phrase semantics and needs language policy; pg_trgm adds extension/index and short-query tradeoffs. Defer them. The existing B-tree indexes may help filtering/ordering but do not accelerate arbitrary substring matching. Scans, TOAST/body reads and offset costs grow with data size; no latency or production-capacity claim is made. Three projections are a deliberate consistency/storage tradeoff for defined bilingual matching, not a measured optimization.

New schema is permitted only in synthetic disposable test databases if this packet is approved. No startup migration, retained-data backfill or existing database operation. A deployed/retained database will need a separately approved versioned migration/backfill before search can be released there.
