## Catalog and assignment rules

Tutor creates, renames and deletes unused tags. Name uses .NET outer Trim, then requires1–50 UTF-16 units; reject NUL, Unicode Cc controls and malformed Unicode. Display preserves the trimmed name, including internal spaces and accents. A global unique key uses existing `TextSearch.Key` (`NFC(ToUpperInvariant(NFC(value)))`) with deterministic C collation. Thus NFC/NFD/case variants collide; accents and đ remain distinct. No compatibility normalization or internal-space collapse. Case-only/display-spelling rename of the same tag is allowed with latest version. An identical trimmed display-name retry at current version is a no-op (no version/audit increment). No two different tag IDs share a normalized key.

Tags are reusable source metadata with UUID/version, not fixed enums. Catalog cap1,000 includes unused terms. Explicit confirmed delete is allowed only with zero active AND archived text references; never cascade/detach sources to make deletion succeed. A once-used tag may be deleted after every source explicitly detaches it; student history does not exist in this packet. Referenced tag rename changes its live display label everywhere; IDs/assignments remain stable, source text/body/version/updatedAt remain unchanged. This is intentional catalog-label behavior, not a student-content snapshot policy.

Text create/edit saves the entire selected tag-ID set atomically with title/description/body/folder and existing content version. Zero to20 unique IDs; reject repeated IDs or >20 supplied entries, invalid UUID types and unknown IDs without partial writes. No implicit tag creation during text save. On create, omitted/null tagIds means empty; on edit, omitted/null means preserve the saved assignment (compatible older clients); an explicit empty array clears all tags. Current UI always submits the complete array. Selection order has no meaning. Archived texts retain references and are read-only; archive/restore preserve them. Existing archived-edit/stale guards win before any tag mutation.

## API and relational implementation

All paths below sit under existing tutor-only `/api/v1/content`, preserving role/session/case/origin/CSRF/no-store handling. Authorization precedes catalog/query validation. No student/author selectors. Tag DTO is `{id,name,version}`; text detail/summary gains `tags:[{id,name}]`, at most20, sorted normalized name then ID. No author, normalized key, references/private metadata or teaching body in summaries. Existing content fields remain compatible.

| Operation | Proposed contract |
|---|---|
| `GET /content/tags` | Full capped catalog ordered normalized key then ID; no query keys accepted. No total/reference count. |
| `GET /content/tags/{id}` | Tag DTO; missing404 `tag_missing`. |
| `POST /content/tags` | `{name}` →201 DTO/Location; strict payload. |
| `POST /content/tags/{id}` | `{name,version}` →200 DTO; current positive version required. |
| `POST /content/tags/{id}/delete` | `{version}` →204 only when unused; confirmation in UI. |
| Existing text create/edit | Add optional `tagIds: UUID[] / null` with omission semantics above; retain content optimistic concurrency and metadata-only content audit. |
| Existing `GET /content` | Add one `tagId=<UUID>` or `tagId=untagged`; omitted means all tags. A valid absent UUID yields empty, malformed/empty400 `invalid_tag_filter`. Repeated tagId400 `invalid_tag_filter`; existing other selector errors unchanged. |

Errors: invalid name400 `invalid_tag_name`, invalid/repeated/oversized tag set400 `invalid_content_tags`, missing tag404 `tag_missing`, duplicate normalized name409 `tag_name_exists`, stale tag409 `tag_stale`, referenced delete409 `tag_in_use`, catalog cap409 `tag_limit`. Typed malformed JSON remains existing400 `invalid_request`. Unknown payloads/queries rejected. Responses contain stable codes, never echo submitted tag names/IDs or SQL exceptions. Audit uses actor/action/target/time only (`tag_create`, `tag_edit`, `tag_delete`); no tag names, query or source body in logs/audit. Existing mutation CSRF/origin tests remain.

Add `ContentTag` with tutor-author restrictive FK, name, normalized key unique index and concurrency version. Explicit `TextContentTag` join has composite PK `(TextContentId,TagId)`, restrictive FKs on both sides and reverse `(TagId,TextContentId)` index for filter/delete checks. Configure delete behavior explicitly instead of inheriting ORM cascade defaults. Service enforces caps under the existing transaction-scoped content advisory lock. All catalog writes and content tag replacement share that lock with existing folder/content writes; validate version/name/cap/references inside the transaction. This serializes delete-vs-assign and duplicate-create races across processes; DB keys/FKs back integrity. Audit failure rolls back catalog/link/source changes together. No per-text content version bump for catalog-only rename; content tag-set edits increment the existing content version.

Apply tag filter as a parameterized server-side EXISTS/NOT EXISTS before existing archive/folder/q/order/skip/take; no joins that duplicate text rows or post-page filtering. Preserve updatedAt-desc/ID-asc ordering, lookahead, maximum-page rule and no total count. Populate tag labels in one bounded batch query for the selected summary IDs after paging (at most101×20 links), not one query/text or a full teaching-body/library download. Empty page needs no label batch. Detail reads fetch only its bounded label set. Catalog labels are live; cross-request rename/concurrent page edits do not provide snapshot isolation, consistent with current paging behavior.

No new dependency, search index/extension or service. Microsoft documents [join entities](https://learn.microsoft.com/en-us/ef/core/modeling/relationships/many-to-many) and [unique/composite indexes](https://learn.microsoft.com/en-us/ef/core/modeling/indexes); those primary references were checked2026-10-29. The proposed schema/query/locking combination is a design inference and must be proven against pinned EF/Npgsql10 and the real disposable PostgreSQL18.6 image. No new migration/backfill or existing database operation in this planning packet; implementation may create schema only in test-owned disposable DBs. Retained-data release needs separately approved versioned schema/backfill, including prior C1b/C1c changes.

## Bilingual UI and state

Use the existing library organization pattern: labeled native “Tag” selector with “All tags” / “Untagged” / catalog options, plus New tag and Edit tag for a selected real term. Inline create/rename form, current-version save, Cancel, explicit unused-only delete confirmation and stale reload/discard confirmation. An in-use failure explains active/archived references and preserves the name. Catalog loading/error/Retry is independent of folders/text-list requests. No nested forms, route/URL storage or new navigation system.

Editor has an optional labeled native tag select and Add button, a selected-tag list with individually named Remove buttons and a20-tag limit hint. Existing terms only; tutor creates catalog terms in the library before editing a text. Do not navigate away or reset a text draft to create a term. Select/Add/Remove changes only the draft until Save; no per-tag content write. Show unavailable selected IDs explicitly if another tab deletes an unassigned-but-drafted term; preserve the draft and block/handle save with a useful `tag_missing` error until selection is repaired. A saved selected term cannot disappear through delete because its FK/reference guard blocks that action. Archived reader shows inert tag labels, no assignment controls.

Single tag filter intersects current direct folder/unfiled/all, active/archive and applied text query. Changing tag/folder/status resets page1 without submitting/discarding draft q. Retry/next/previous keep the applied tuple; same C1c no-match/out-of-range rules. Tag rename preserves selected tag ID/filter and refreshes labels/results without altering q. Successful unused-tag delete resets selected tag filter to All and page1. Catalog create does not automatically filter away existing results. Catalog mutation refreshes texts from page1. No tag-name expansion of q or automatic content assignment.

Both typed dictionaries cover labels/hints/caps, selection/removal accessible names, loading/empty/error/notices/validation/confirmation. Locale changes preserve tag/text/folder/query drafts, filter/page, focus/selection and in-flight requests without refetch or remount. Request generation/cleanup guards and existing account epoch reject stale success/error/account bytes. Recoverable errors never silently clear tags or overwrite a draft; explicit reload confirmation discards it. Keyboard/44px targets and deep-blue/white styling remain. User-written tag names stay untranslated and inert React text. No tags in browser storage or student navigation.
