## Concrete experience and lifecycle

1. A loaded active or archived text offers a secondary **Create a copy / Tạo bản sao** action. In the active editor it is unavailable while there are unsaved changes, a mutation pending, stale-conflict state or an open confirmation. Explain **Save or discard your edits before creating a copy / Lưu hoặc bỏ các thay đổi trước khi tạo bản sao**. Do not save or discard automatically. Retain the existing explicit reload/discard interaction.
2. Navigate to `/content/{sourceId}/copy`. Load the saved detail through the existing authenticated GET. Display **New text from a copy / Nội dung mới từ bản sao**, the source title, and **Nothing is saved until you create the copy / Bản sao chỉ được lưu khi bạn chọn tạo bản sao**. Missing/unavailable source shows recoverable loading/error state with retry and return to library; never fall back to a blank creatable draft after a failed read.
3. Populate title, description, body, folder and tag selections from that one successful saved detail response. Keep the title exactly as authored, including a 200-character title; duplicate titles are already legal. Do not append a translated suffix or truncate content. Source attribution in the heading distinguishes the draft. The tutor may edit any field before saving.
4. **Create copy / Tạo bản sao** explicitly POSTs the draft as a new text. Success navigates to the new ID and shows the existing localized creation notice. New row is active even when the source was archived, has a new ID, version 1, current tutor author and fresh timestamps. Source fields/version/timestamps/archive status remain unchanged. New tag associations refer to the same reusable catalog tags; folder is a shared organizational reference, not a cloned folder. Later tag renames remain global by existing C1d rules, while each text's selected tag set and text fields can change independently.
5. No write occurs on entering, editing or leaving the copy draft. Cancel returns to the source; a dirty draft requires an inline discard confirmation, with cancel returning focus to its trigger. Browser reload/back and session revalidation retain existing ephemeral draft limitations: do not promise persistence or expand to a global navigation blocker. Leaving/remounting/reloading starts a new saved-source read; later source changes never silently overwrite an already initialized draft.

Source may change/archive after the read: copy deliberately uses the saved values loaded into this draft, not a claim of latest-version cloning. No source-version precondition is sent because source is not mutated. If source disappears after a successful read, saving the already loaded values remains an ordinary independent create; failure before that read cannot create. Concurrent folder/tag deletion is rejected by existing create validation. Preserve text and remaining selections, refresh the relevant catalog and require explicit selection repair/clear before resubmitting; never silently drop missing metadata. Catalog rename resolves to current labels without altering typed values. Archived source copying does not restore it.

## API, data and security contract

No API/DTO/schema change. Use `GET /api/v1/content/{id}` returning existing TextDetail and `POST /api/v1/content` with `{title, description, body, folderId, tagIds}` returning 201/TextDetail/Location. Omit source ID, version, author, timestamps, archive flag and any activity data from the create payload. Existing limits remain title 200, description 2000, body 50000 and at most 20 distinct existing tags; preserve Unicode/plain-text rendering and current server validation.

Existing create transaction takes the content lock, validates folder/tags, projects search fields and atomically saves text, tag associations and `content_create` audit. No new duplicate audit or provenance field is needed. Failure creates neither partial content nor audit. No copying students, grants, notes, answers, files, submissions, scores or deadlines. No student route; existing server tutor/mandatory-password/session/case-variant/CSRF/origin controls remain authoritative. No sensitive draft in URL, history state, storage or logs; URL contains only source UUID. The ephemeral form clears through existing session lifecycle.

Prevent double-submit with a synchronous in-flight guard as well as disabled controls; language changes must not submit/refetch. No automatic mutation retries. Existing create is not idempotent: a timeout/network failure can occur after commit. For uncertain outcomes retain draft but show a specific localized notice to check the library before explicitly retrying, since retry may create another copy. Do not claim exactly-once semantics or add an idempotency store in this slice. Late reads/responses from another source/route/session must not overwrite a newer editor or navigate it; use existing client epoch plus route-local response ownership. Reset editor state on route/source identity only, never locale.
